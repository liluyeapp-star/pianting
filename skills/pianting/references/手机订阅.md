# 用个人 RSS 在手机收听

本步骤是可选项。精剪完成后得到的 MP3 可以直接播放；只有想让新节目持续出现在同一个播客订阅中时，才需要建立个人 RSS。

## Cloudflare 在这里做什么？

Cloudflare 是让文件长期在线的托管服务。这里用 **Pages** 存放 MP3、RSS 和简单播放页，用生成的 **Worker** 处理播放器的分段请求，让进度条可以拖动；**Wrangler** 是把这些文件发布到你账号里的命令行工具。剪辑和飞书转写不在 Cloudflare 上运行，电脑关机后已发布的节目仍可访问；增加新节目时才需要再次运行本地工具并部署。

GitHub 提供这套工具的源码，不会随安装自动附送云空间。每位使用者要使用自己的 Cloudflare 账号和项目。这个方案不需要购买域名或服务器，也没有用到 R2 存储；项目会提供 `pages.dev` 地址。更换其他托管商在原理上可行，但当前构建器按 Pages 的 25 MiB 限制检查，Worker 模板也使用 Cloudflare 的运行环境；其他方案需要适配和验证。

这个 RSS 不会自动发布到公开目录，也不会带来账号鉴权。知道完整订阅链接的人可以访问它，因此请勿公开分享。构建工具会随机生成一个长路径，并添加禁止搜索引擎收录的标记；这只是减少被发现的机会，不能替代权限控制。

## 需要准备

- 一个自己的 Cloudflare 账号，初次使用者到 [Cloudflare 控制台](https://dash.cloudflare.com/) 注册或登录，再按下文创建 Pages 项目。
- 已完成的本地 MP3。原始高音质文件请另行保留；若手机版超过上限，需要自行转码并在音质与文件大小之间取舍。
- Python 3.9 或更高版本，以及能运行 `node`、`npm`、`npx` 的 [Node.js 环境](https://nodejs.org/)。本教程采用 Wrangler 命令行部署。

构建脚本只生成文件，不会自动登录、注册账号或发布。Cloudflare Pages 和 Wrangler 的界面、命令会更新，遇到差异以 [官方部署文档](https://developers.cloudflare.com/pages/get-started/direct-upload/) 为准。

## 先登录并创建空项目

```bash
npx wrangler login
npx wrangler whoami
npx wrangler pages project create <自己的项目名> --production-branch main
```

`login` 会打开浏览器，请在你自己的账号下完成授权；出现 “Authorization granted to Wrangler” 表示命令行获得了授权，不等于已经部署。`whoami` 用来核对账号，已有多个账号时需选定正确的账号。不要将其账号信息或登录缓存提交到 GitHub。

项目只创建一次，后续继续使用它。记下控制台显示的实际生产域名，用它填写下方 `--base-url`，不要把每次部署生成的预览域名当作固定订阅地址。如果项目名已被占用，实际域名可能带额外字符。

## 第一次创建资料库

在这个仓库根目录运行（替换尖括号中的内容）：

```bash
python3 skills/pianting/scripts/build_feed.py \
  --library-dir "<你自己的资料库目录>" \
  --base-url "https://<你的项目名>.pages.dev" \
  --audio "<剪好的 MP3 文件>" \
  --episode-id "episode-001" \
  --title "节目名｜嘉宾原声版" \
  --source-url "https://<原节目公开出处>" \
  --duration 1800
```

`--duration` 是剪辑完成后的秒数。命令会生成：

- `<资料库目录>/public/`：唯一允许上传的目录，包含 RSS、网页、音频和用于音频拖动的 `_worker.js`。
- `<资料库目录>/state.json` 与 `catalog.json`：本地状态，保存随机路径和固定 GUID。**不要上传或分享它们。**

## 发布生成的文件

完成上面的登录、创建项目和本地构建后，用 Wrangler 发布：

```bash
npx wrangler pages deploy "<资料库目录>/public" --project-name <自己的项目名> --branch main
```

首次创建项目一次即可；后续只运行 deploy。项目域名必须和构建时的 `--base-url` 一致。命令如果因版本变化报错，按上面的官方文档与 `npx wrangler pages --help` 核实，不盲目重建资料库。

首次部署和后续更新都上传整个 `public/` 目录到你自己的 Pages 项目。不要上传资料库根目录。Pages 的静态资源默认可能不能正确处理播放器的 Range 请求；生成的 `_worker.js` 会为清单中的 MP3 返回标准的 206 分段响应，支持拖动进度。

部署后先核验：RSS 能打开且列出正确的节目；MP3 的 HEAD 返回正确长度；请求音频首段、中段、末段时返回 `206`；实际下载音频与本地文件一致。最后在手机里播放和拖动一次。只看到部署成功，不代表音频和订阅都已验收。

## 在播客应用中添加

部署成功后，订阅地址是：

```text
https://<你的项目名>.pages.dev/<随机路径>/feed.xml
```

在 iPhone 的苹果播客中，进入“资料库”，选择右上角“…”并选择“通过 URL 关注节目”，粘贴该地址。其他支持 RSS 的播客应用也可使用同一个地址。

这是通过地址关注个人节目，不需要注册 Apple Podcasts 创作者账号或向公开目录提交节目。小宇宙能提供原节目网页音源，不代表它也接受任意个人 RSS；当前尚未验证小宇宙内的个人订阅导入。

## 添加下一期

对每一份新的精剪再次运行相同命令，换掉 `--audio`、`--episode-id`、`--title`、`--source-url` 和 `--duration`，但保持 `--library-dir` 与 `--base-url` 不变。随后重新上传整个 `public/` 目录。已有单集、随机路径和 GUID 会保留，订阅者会把它识别为同一个节目。

如果重复使用同一个 `--episode-id`，它会更新这一集的音频和标题，但仍保留其 GUID；不要用它覆盖不同的节目。

## 免费额度与长音频

以下限制核对于 2026-09-16，后续以官方说明为准：

- Pages 单个静态文件最大 **25 MiB**，不是可以靠本工具绕过的限制。详见 [Pages 资源限制](https://developers.cloudflare.com/pages/platform/limits/)。
- 不触发 Functions 的纯静态请求与本项目的 Worker 请求不同。本项目使用 `_worker.js`，其调用计入 Workers / Pages Functions 额度。Free 计划当前合计为每天 **100,000 次请求**，与同账号其他 Worker 共用；这不是 100,000 次完整播放。详见 [Functions 计费与免费额度](https://developers.cloudflare.com/pages/functions/pricing/)。
- 本教程按免费方案起步，脚本不会自动升级套餐。额度用尽或平台政策变化时，收听可能受影响；需要付费或迁移时由使用者决定。

文件大小粗估：`MB ≈ 秒数 × kbps ÷ 8000`。例如一小时 64 kbps 约 28.8 MB，会超过 25 MiB；56 kbps 约 25.2 MB，需以实际文件大小为准。语音可以生成单声道手机版，完整版保留在本地：

```bash
ffmpeg -i "guest.mp3" -ac 1 -ar 44100 -c:a libmp3lame -b:a 56k "guest-mobile.mp3"
```

这是体积与音质的取舍，不会提高原音质；56 kbps 也不能保证任意时长都合规。仍然超限时可拆分单集，或另行适配支持大文件的托管方案。当前工具不自动开通 R2，也不自动降低码率。
