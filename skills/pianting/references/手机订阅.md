# 用个人 RSS 在手机收听

本步骤是可选项。精剪完成后得到的 MP3 可以直接播放；只有想让新节目持续出现在同一个播客订阅中时，才需要建立个人 RSS。

这个 RSS 不会自动发布到公开目录，也不会带来账号鉴权。知道完整订阅链接的人可以访问它，因此请勿公开分享。构建工具会随机生成一个长路径，并添加禁止搜索引擎收录的标记；这只是减少被发现的机会，不能替代权限控制。

## 需要准备

- 一个自己的 Cloudflare 账号和一个 Cloudflare Pages 项目；免费计划的静态资源单文件上限是 25 MiB。
- 已完成的本地 MP3。原始高音质文件请另行保留；若手机版超过上限，需要自行转码并在音质与文件大小之间取舍。
- Python 3.9 或更高版本。这个构建步骤不需要 Pillow，也不会自动登录、创建或发布 Cloudflare 项目。

Cloudflare Pages 和 Wrangler 的界面、命令会更新。先以 [Cloudflare Pages 的官方 Wrangler 部署文档](https://developers.cloudflare.com/pages/get-started/direct-upload/) 为准，完成自己的登录和项目创建，再执行下面的构建命令。

## 第一次创建资料库

在这个仓库根目录运行（替换尖括号中的内容）：

```bash
python3 skills/pianting/scripts/build_feed.py \
  --library-dir "<你自己的资料库目录>" \
  --base-url "https://<你的项目名>.pages.dev" \
  --audio "<剪好的 MP3 文件>" \
  --episode-id "episode-001" \
  --title "节目名｜嘉宾原声版" \
  --source-url "https://<原节目公开出处>" \
  --duration 1800
```

`--duration` 是剪辑完成后的秒数。命令会生成：

- `<资料库目录>/public/`：唯一允许上传的目录，包含 RSS、网页、音频和用于音频拖动的 `_worker.js`。
- `<资料库目录>/state.json` 与 `catalog.json`：本地状态，保存随机路径和固定 GUID。**不要上传或分享它们。**

用 Wrangler 发布（需要 Node.js，首次运行会安装 Wrangler 并要求 Cloudflare 登录）：

```bash
npx wrangler login
npx wrangler pages project create <自己的项目名> --production-branch main
npx wrangler pages deploy "<资料库目录>/public" --project-name <自己的项目名> --branch main
```

首次创建项目一次即可；后续只运行 deploy。项目域名必须和构建时的 `--base-url` 一致。命令如果因版本变化报错，按上面的官方文档与 `npx wrangler pages --help` 核实，不盲目重建资料库。

首次部署和后续更新都上传整个 `public/` 目录到你自己的 Pages 项目。不要上传资料库根目录。Pages 的静态资源默认可能不能正确处理播放器的 Range 请求；生成的 `_worker.js` 会为清单中的 MP3 返回标准的 206 分段响应，支持拖动进度。

## 在播客应用中添加

部署成功后，订阅地址是：

```text
https://<你的项目名>.pages.dev/<随机路径>/feed.xml
```

在 iPhone 的苹果播客中，进入“资料库”，选择右上角“…”并选择“通过 URL 关注节目”，粘贴该地址。其他支持 RSS 的播客应用也可使用同一个地址。

## 添加下一期

对每一份新的精剪再次运行相同命令，换掉 `--audio`、`--episode-id`、`--title`、`--source-url` 和 `--duration`，但保持 `--library-dir` 与 `--base-url` 不变。随后重新上传整个 `public/` 目录。已有单集、随机路径和 GUID 会保留，订阅者会把它识别为同一个节目。

如果重复使用同一个 `--episode-id`，它会更新这一集的音频和标题，但仍保留其 GUID；不要用它覆盖不同的节目。
